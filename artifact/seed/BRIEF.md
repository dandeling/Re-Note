# 예시 데이터 만들기

학생·초보 연구자의 탐구(연구)와 그 과정에서 겪은 고충을 모아 보는 서비스의 **예시 데이터**를 만든다. 검색 품질을 시험하고 처음 온 사람이 둘러볼 수 있게 하려는 것이다. 모두 지어낸 예시이며 실제 사람·학교·논문을 가리키지 않는다.

## 출력
배정받은 파일 하나에 JSON 배열을 쓴다(UTF-8, 유효한 JSON, 주석 없음). 원소 50개, 각 원소:
```json
{
  "title": "연구 제목 (20~45자, 무엇을 어떻게 했는지 드러나게)",
  "field": "배정받은 분야 이름 중 하나 (그대로)",
  "keywords": ["3~5개", "각 2~12자", "검색에 쓸 만한 낱말"],
  "summary": "요약 2~3문장(120~220자). 무엇을 만들고/측정하고, 어떤 방법으로, 어떤 결과(구체적인 수치·단위 포함)를 얻었는지.",
  "limitations": "한계 1~2문장(60~140자). 실제로 그 연구에서 생길 법한 구체적인 한계(표본 수, 측정 오차, 통제 못 한 변인, 장비 한계 등).",
  "pains": [
    { "title": "고충 제목 (15~40자, 막힌 점이 드러나게)", "body": "본문 2~3문장(80~200자). 무엇을 하다 어디서 막혔는지, 무엇을 시도했는지. 질문으로 끝나도 좋다.", "stage": "TOPIC|DESIGN|EXPERIMENT|ANALYSIS|REPORT|OTHER 중 하나", "tags": ["2~3개"], "resolution": "선택: 해결했다면 해결 방법 1~2문장", "anonymous": false },
    { "…": "고충은 연구마다 정확히 2개" }
  ]
}
```
- `resolution`은 고충의 약 1/3에만 넣는다(없으면 키 자체를 뺀다). `anonymous: true`는 약 1/8에만(없으면 false).
- `stage`는 고르게 섞는다(주제선정·설계·실험·분석·보고서작성·기타).

## 품질 기준
- 중·고등학생~학부 저학년이 학교나 집에서 실제로 할 수 있는 수준의 탐구. 주제가 서로 겹치지 않게 50개 모두 다르게(같은 소재의 변주 금지).
- 수치와 단위는 그럴듯하고 서로 모순이 없게(예: 평균과 표준편차, 온도 범위, 표본 수).
- 문체는 "~했다", "~확인했다" 같은 보고서체(연구), 고충 본문은 "~해요/~합니다" 같은 자연스러운 말투.
- 고충은 그 연구에서 실제로 막힐 만한 구체적인 문제(장비, 측정, 통계, 보고서 서식, 주제 정하기, 팀 작업, 일정 등). "어려워요" 같은 막연한 글 금지.
- 실존 인물·학교·회사·상품명·논문 제목을 쓰지 않는다. 위험한 실험(폭발물, 독성 물질 합성, 병원체 배양 조작, 사람·동물에 해를 주는 실험)은 넣지 않는다. 사람 대상 설문은 동의를 받는 평범한 수준으로.
- 이미 있는 예시 30건(`/home/user/prisma/seed-data.ts`의 `SEED_RESEARCH` 제목들)과 주제가 겹치지 않게 먼저 읽고 피한다.

## 확인
다 쓴 뒤 `python3 -I - <<'PY'`로 파일을 읽어 검사한다: 유효한 JSON, 원소 정확히 50개, 필수 키, 고충 2개씩, stage 값, 제목 중복 없음, 길이 범위. 통과하지 못하면 고친다. 다른 파일은 건드리지 않는다. 끝나면 한두 줄로 보고(파일 경로, 개수, 분야별 개수).
