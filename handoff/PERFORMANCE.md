# 만드는 속도 개선 방안 — 170분, 두 번 실행으로 끝내기

> 새 AI 에이전트와 실행하는 사람에게 넘기는 문서. 사용자가 말한 "느린 것"은 앱이 아니라 **만드는 과정**이다.
> 형식: `handoff/PROMPT.md`와 `handoff/SPEC.md`를 넘겨 **1차 실행** → 사람 점검 → **2차 실행**. 실행 중에는 대화하지 않는다.
> 근거 표시: [git] 커밋 기록 · [문서] SPEC 표 A·B, `docs/decisions.md`, `docs/parallel-work.md`, `docs/acceptance.md` · [기록] 작업 중 전달받은 사실 · [추정] 위 자료에서 이끌어 낸 판단. 커밋 사이 빈 시간의 정체는 알 수 없다.

- 선택: 디자인 다듬기, PDF 업로드, [W] 체험판.

## ④ 프롬프트 틀

1차:
```
SPEC.md와 PROMPT.md대로 [A]만 만든다. 질문하지 말고 결정은 docs/decisions.md에 기록한다.
범위: 필수 → (남으면) 선택. 제외는 만들지 않는다. 뼈대를 먼저 게시하고 모듈마다 다시 게시한다.
종결: 필수가 모두 [x]이고 artifact/tests 전부 통과, 또는 20:25(한국 시간)이면 강제 종료.
20:10에 전체 테스트를 한 번 돌리고, 20:15부터는 새 작업 없이 정리만 한다.
끝낼 때 PROGRESS.md, RESULT.md(완료/미완/검증 못 한 것), HUMAN_CHECK.md(실제 환경에서 사람이 15분 안에 볼 것, 15개 이내: 어디서/누르는 것/보여야 하는 것)를 남기고 5줄로 보고한다. 리뷰는 생략한다.
```

2차:
```
1차의 PROGRESS.md·decisions.md·RESULT.md·HUMAN_CHECK.md(결과 칸 포함)와 아래 보완점 표로 이어서 한다. 질문하지 않는다.
순서: 보완점 "꼭" → 1차 미완 필수 → "가능하면". 21:10에 전체 테스트를 돌리고, 21:25부터 정리만, 21:35에 강제 종료한다. 끝낼 때 같은 파일들을 갱신한다.
| # | 꼭/가능하면 | 어디 | 지금(화면 글자) | 원하는 것 | 끝난 기준 |
```
