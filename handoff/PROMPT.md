# PROMPT.md — Re: Note 대회용 (두 번 실행)

대회 시간은 **19:00~21:50 (170분)** 이다. 프롬프트는 **딱 두 번** 보낸다. 실행 중에는 에이전트에게 말을 걸지 않는다.

## 시간표

| 시각 | 할 일 | 누가 |
|---|---|---|
| 19:00 | SPEC.md를 작업 폴더에 넣고 **[1차 프롬프트]** 를 그대로 붙여 넣는다 | 사람 (1번 클릭) |
| 19:00~20:25 | 1차 실행. 20:25에 스스로 멈춘다 | 에이전트 |
| 20:25~20:40 | `HANDOFF.md`의 "사람이 볼 것"을 따라 결과물을 눌러 보고 **[보완 양식]** 을 채운다 | 사람 (15분) |
| 20:40 | **[2차 프롬프트]** 에 채운 양식을 붙여 보낸다 | 사람 (1번 클릭) |
| 20:40~21:35 | 2차 실행. 21:35에 스스로 멈춘다 | 에이전트 |
| 21:35~21:50 | 최종 확인과 제출 | 사람 |

시작이 늦어지면 프롬프트 안의 시각 두 군데(1차 20:25, 2차 21:35)만 고쳐서 보낸다.

## [1차 프롬프트] — 이 블록 전체를 그대로 붙여 넣는다

```
/loop 너는 "Re: Note"를 처음부터 만드는 에이전트다. 작업 폴더의 SPEC.md를 끝까지 읽고 시작해라.

[목표]
아래 우선순위대로 아티팩트판([A]) 하나를 만든다. 웹 체험판([W])과 서버 앱([S])은 만들지 않는다. SPEC.md에서 [S]·[W]만 해당하는 내용은 건너뛴다.
P0를 전부 끝낸 뒤 P1, 그다음 P2 순서로 한다. P0가 끝나기 전에는 P1·P2에 손대지 않는다.
- P0 (반드시): 공통 뼈대·디자인·화면 이동 / 예시 데이터와 둘러보기 모드 / 연구 탐색·검색·상세 / 고충 게시판(작성·공감·해결 표시, 댓글 없음) / 내 프로젝트와 문서 에디터 기본(문단·제목·목록·굵게, 자동 저장, 새로 고침 뒤 유지) / 연구 공개
- P1 (그다음): 표·그림·캡션 번호 / 수식(쉬운 입력) / 마크다운·DOCX 내보내기 / CSV → 표·그래프 / 한글 파일 열기(HWPX 먼저, HWP5는 그다음)
- P2 (시간이 남을 때만): 챗봇 / 의미로 더 찾기 / 글쓰기 자동완성 / 결과보고서 PDF 업로드 / 서식 템플릿 / 버전 기록
SPEC.md에 "0. 대회 실행 기준" 절이 있으면 그 표가 이 목록보다 우선한다.

[절대 규칙]
1. 나에게 질문하거나 확인을 기다리지 마라. 결정이 필요하면 SPEC.md 14장에 적힌 결정(또는 제안된 기본값)을 따르고, 거기 없으면 가장 단순한 쪽으로 정해 DECISIONS.md에 한 줄로 적고 계속해라.
2. 마감은 한국 시간 20:25다. 반복할 때마다 `TZ=Asia/Seoul date +%H:%M`으로 시각을 확인해라.
   - 20:10이 지나면 새 기능을 시작하지 마라. 하던 것만 끝내거나 되돌리고, 정리와 기록만 해라.
   - 20:25가 되면 무엇을 하고 있든 [끝낼 때 할 일]을 하고 루프를 종료해라.
3. 결과물은 항상 열리는 상태여야 한다. 19:30까지 뼈대(공통 틀 + 홈 + 예시 데이터로 채운 목록)를 게시하고, 기능 하나가 끝날 때마다 로컬 확인 후 다시 게시해라. 게시한 것을 깨뜨리는 변경은 게시하지 마라.
4. 확인하지 않은 것을 "된다"고 적지 마라. 로컬에서 확인한 것 / 실제 게시본에서 확인 못 한 것을 구분해라.
5. 비밀 값을 코드에 넣지 마라. 네가 읽지 않은 파일은 게시하지 마라. 외부 스크립트는 SPEC.md의 아티팩트 제약에 있는 허용 출처만 써라.

[일하는 순서]
1. (10분 이내) SPEC.md를 읽고 PROGRESS.md를 만든다: P0 → P1 → P2 순서의 체크리스트, 항목마다 완료 기준 한 줄.
2. (15분 이내) 공통 뼈대를 혼자 만든다: 공통 스크립트(전역 API, 라우팅, 데이터 접근, 기능이 없을 때의 대체 동작), 페이지 틀과 디자인 토큰, 로컬 확인용 가짜 런타임, 예시 데이터. 모듈 계약(각 모듈이 쓰는 전역 API와 파일 이름)을 CONTRACT.md에 적는다. 그리고 게시한다.
3. 모듈별로 하위 에이전트에게 나눠 맡긴다(동시에 3~4개, 모델은 한 단계 낮은 등급). 한 에이전트는 자기 파일만 고친다. 공통 파일을 고쳐야 하면 네가 직접 고친다. 에이전트에게는 CONTRACT.md, SPEC.md의 해당 절, 담당 파일 이름, 완료 기준, 마감 시각을 준다.
   - 연구 탐색·검색·상세·공개
   - 고충 게시판
   - 내 프로젝트·문서 에디터
   - (P0가 배정된 뒤) P1 모듈들
4. 모듈이 돌아올 때마다: 로컬에서 그 화면을 열어 완료 기준을 직접 확인 → PROGRESS.md 체크 → 다시 게시.
5. 테스트는 고친 모듈의 것만 돌린다. 전체 확인은 20:10에 한 번만 한다.
6. 같은 문제로 세 번 실패하면 그 항목을 BLOCKED.md에 적고 다음 항목으로 넘어가라.

[끝낼 때 할 일] — P0·P1·P2를 전부 끝냈거나 20:25가 되면
1. 마지막으로 동작하는 상태를 게시한다.
2. HANDOFF.md를 쓴다:
   - 결과물 주소와 여는 방법
   - 끝낸 것 / 못 끝낸 것(PROGRESS.md 기준)
   - 스스로 내린 결정(DECISIONS.md 요약)
   - 확인하지 못한 것
   - **사람이 볼 것**: 10분 안에 따라 할 수 있는 번호 목록. "어느 화면에서 / 무엇을 누르면 / 무엇이 보여야 한다" 형식, 실제 게시본에서만 확인되는 것(로그인 표시, 저장, AI, 한글 입력)을 앞에 둔다.
3. 변경을 커밋한다.
4. 루프를 종료한다. 종료 뒤에는 아무것도 하지 마라.

## [보완 양식] — 1차가 끝나면 15분 동안 채운다

`HANDOFF.md`의 "사람이 볼 것"을 순서대로 눌러 보고 아래를 채운다. 빈 항목은 "없음"으로 둔다.

```
[문제] 한 줄에 하나. 형식: 우선순위 / 어디서 / 무엇을 했더니 / 어떻게 됐다 / 어떻게 돼야 한다
- 꼭 / 
- 꼭 / 
- 남으면 / 

[건드리지 말 것] 1차에서 잘 된 것
- 

[추가] 꼭 필요한 것만, 최대 2개
- 
```

채운 예:

```
[문제]
- 꼭 / 문서 편집 / 한글로 쓰다 멈춤 / 제안이 안 뜸 / 흐린 글씨로 이어질 말이 떠야 함
- 꼭 / 고충 게시판 / 글을 쓰고 새로 고침 / 내 글이 목록 맨 위에 없음 / 최신 글이 위에 와야 함
- 남으면 / 홈 / 휴대폰 폭 / 바로 가기 카드가 잘림 / 한 줄에 하나씩 보여야 함

[건드리지 말 것]
- 연구 탐색의 검색과 상세 화면
- 에디터의 자동 저장

[추가]
- 없음
```

```
/loop 너는 "Re: Note"의 1차 결과물을 보완하는 에이전트다. 작업 폴더의 SPEC.md, HANDOFF.md, PROGRESS.md, DECISIONS.md, BLOCKED.md(있으면), CONTRACT.md를 읽고 시작해라. 새로 만들지 말고 있는 것을 고쳐라.

[할 일의 순서]
1. 아래 [사람이 적은 보완점]의 "꼭" 항목 전부
2. PROGRESS.md에서 못 끝낸 P0 항목
3. [사람이 적은 보완점]의 "남으면" 항목과 [추가]
4. 못 끝낸 P1, 그다음 P2
앞 순서가 끝나기 전에는 뒤 순서에 손대지 마라. [건드리지 말 것]에 적힌 부분은 동작이 바뀌지 않게 해라. 그 부분의 파일을 고쳐야 하면 고친 뒤 그 화면을 다시 확인해라.

   - 21:20이 지나면 새 수정을 시작하지 마라. 하던 것만 끝내거나 되돌려라.

5. 확인하지 않은 것을 "됐다"고 적지 마라.
6. 서로 다른 파일의 수정은 하위 에이전트에게 나눠 맡겨도 된다(동시에 3개 이내, 한 에이전트는 자기 파일만).

## 이 프롬프트에 담은 것 — 지난번에 느렸던 원인과 막는 방법

| 지난번에 생긴 일 | 이번 프롬프트의 대응 |
|---|---|
| 프롬프트를 여러 번 나눠 보내며 요구를 추가·변경 | 두 번만 보낸다. 요구는 SPEC.md에 미리 확정, 보완은 양식 한 번 |
| 배포 형태가 여러 번 바뀌어 버린 작업이 많음 | 아티팩트판 하나로 고정 |
| 에이전트가 물어보고 기다림 | 질문 금지, 결정은 DECISIONS.md에 적고 진행 |
| 끝이 정해지지 않아 계속 늘어남 | 시각으로 멈추는 종결 조건, 마감 15분 전 새 작업 금지 |
| 덜 중요한 기능에 시간을 씀 | P0 → P1 → P2 순서 강제 |
| 병렬 에이전트가 같은 파일을 고쳐 충돌 | 모듈별 파일 소유권, 공통 파일은 주 에이전트만 |
| 전체 테스트를 자주 돌려 시간 소모 | 고친 모듈만 테스트, 전체는 한 번 |
| 실제 화면을 에이전트가 못 봐서 추정 수정 반복 | 1차 끝에 "사람이 볼 것" 목록, 사람이 양식으로 한 번에 전달 |
| 조용히 실패해 원인을 못 찾음 | 상태를 화면에 보이게 하는 규칙 |
| 확인 안 된 것을 완료로 보고 | 확인한 것과 못 한 것을 구분해 적게 함 |
